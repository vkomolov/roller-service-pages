# Gulp Build System

This guide describes how files move from `src/` to `dist/`, how the `dev` and `build`
pipelines differ, and what each declared npm package contributes to the project.

## 1. Build entry points and configuration

- `gulpfile.js` is the Gulp entry point. It chooses the mode, cleans generated output, starts
  the pipeline, and optionally starts BrowserSync and file watchers.
- `gulp/paths.js` defines source globs, output folders, languages, page metadata, and Webpack
  entry files.
- `gulp/settings.js` defines HTML context, PostCSS plugins, Webpack settings, and SVG sprite
  options.
- `gulp/tasks.js` contains the mode-specific streams.
- `gulp/utilFuncs.js` contains shared file, page-data, and stream helpers.
- `modules/` contains project-specific Gulp transforms and the BrowserSync wrapper.

The root `src/html/*.html` files are Gulp's HTML inputs. `src/html/templates/` is included
from those pages; it is not separately emitted as a page. SCSS entry points are the root
files in `src/scss/` (currently `index.scss` and `critical.scss`), which import nested
partials. The JavaScript entry is `src/js/index.js`. Static sources are under `src/assets/`,
with root-level utility files such as `src/_redirects` and `src/robots.txt`.

## 2. Full pipeline and ordering

`runPipes()` in `gulpfile.js` executes these stages in order:

1. **Clean:** remove `dist/`, `zip/`, and `src/temp/`.
2. **Collect static resources, in parallel:** process images, copy fonts and data, generate
   both SVG sprites, and copy root-level utility files.
3. **Compile styles and scripts, in parallel:** compile the SCSS entry points and bundle the
   JavaScript with Webpack.
4. **Compile HTML last:** generate one localized site per language, including the correct
   page data and resource metadata.

HTML is last because its image transform checks the already-written `dist/` image files to
see whether a WebP or retina variant exists. The parallel work inside a stage is independent;
the stage boundaries are significant.

## 3. File-by-file processing

| Input | Processing | Output |
|---|---|---|
| Root HTML pages | `gulp-file-include` expands `@@include` and `@@if` using the selected language's JSON data. Image tags outside an existing `<picture>` may be wrapped with WebP sources when the generated WebP exists. Development output is beautified; production HTML is cleaned. | `dist/uk/*.html` and `dist/ru/*.html` |
| Root SCSS entry points and imported SCSS | Dart Sass compiles each entry. PostCSS sorts media queries mobile-first, runs Autoprefixer, `postcss-discard-unused`, and cssnano. The pipeline writes optimized CSS and a `.min.css` variant; only production runs the additional whitespace-normalization pass before writing the `.min.css` file. | `dist/css/index.css`, `index.min.css`, `critical.css`, and `critical.min.css` |
| `src/js/index.js` | Webpack bundles the entry; Babel transforms project JavaScript. Webpack splits non-GSAP dependencies into the vendor entry and emits the dynamic GSAP chunk separately. | `dist/js/index.bundle.js`, `vendor.bundle.js`, and the asynchronous GSAP chunk |
| Raster images | Development copies originals and creates WebP from JPEG/PNG. Production copies originals, creates WebP from JPEG/PNG, and optimizes supported output formats with Sharp; SVG optimization uses SVGO. | Matching relative paths under `dist/assets/img/` |
| `svgIcons/mono` and `svgIcons/multi` SVG files | Custom sprite transforms optimize and combine each folder into symbols. These source icon folders are excluded from the ordinary image-copy task. | `dist/assets/img/svgIcons/sprite.mono.svg` and `sprite.multi.svg` |
| Fonts | Binary copy, preserving subdirectories and file names. | `dist/assets/fonts/` |
| JSON, PDF, and XML under `src/assets/data/` | Binary copy. The page JSON is also read from `src/` to produce localized HTML. | `dist/assets/data/` |
| Files at the root of `src/` | File-only copy, including hidden files; directories are filtered out. | `dist/` (for example `_redirects` and `robots.txt`) |

`gulp-changed` is used in selected development streams to skip files whose contents have not
changed. It is not a production optimization stage. The project includes a custom PurgeCSS
transform, but the call to it in the production style stream is commented out. Do not describe
the current build as removing selectors by matching CSS against HTML: the active PostCSS
plugin `postcss-discard-unused` is not that HTML-aware PurgeCSS pass.

## 4. Development, production, and watch mode

### Development

Run `npm run dev`. After the required Node version check, Gulp cleans and executes the `dev`
pipeline, starts BrowserSync at `/uk/index.html`, and registers watchers.

- Sass and JavaScript source maps are enabled.
- SCSS output is not run through the production whitespace-normalization pass. The
  `.min.css` file is still generated by renaming the already-optimized CSS stream, so the
  suffix does not imply the same whitespace processing as the production file.
- Images are copied and JPEG/PNG inputs are converted to WebP without the production image
  optimization pass.
- HTML is beautified.
- Watchers rebuild the relevant stream and reload the preview. A JSON/data change copies data
  and recompiles HTML; a nested SCSS change recompiles the root style entries.

`npm run pipesDev` runs the same build pipeline without BrowserSync or watchers.

### Production

Run `npm run pipesBuild` for build-only output, or `npm run build` to generate it and start a
BrowserSync preview. Webpack uses production mode, Sass has no source maps, HTML is cleaned,
and images receive the production optimization pass. Styles are first written as optimized
CSS, then pass through `postcss-normalize-whitespace` and are renamed with `.min.css`.

This is a static site build; BrowserSync is only a local preview server and is not part of the
deployed output.

### Watch coverage

Watch patterns are in `gulp/paths.js`: nested HTML, SCSS (including the gallery module's
SCSS), JavaScript, ordinary images, each icon folder, fonts, and JSON/PDF/XML data. Templates
are covered by the nested HTML glob. The HTML watcher recompiles HTML, while the data watcher
copies data and then recompiles HTML.

### Installed packages and helpers outside the default pipeline

- **PurgeCSS (`purgecss`, `modules/CustomPurgeCss.js`):** the transform is present but its
  invocation in `gulp/tasks.js` is commented out. It searches for an HTML file with the same
  basename as each CSS file and purges against that HTML. This can be useful for an optional
  single-page/single-language build when each stylesheet has a matching HTML file. The
  current site generates multiple pages and languages, so enabling this unchanged can select
  the wrong HTML file and remove selectors needed by other pages or languages. In addition,
  the current pipeline compiles styles before generated HTML, while this transform searches
  under the generated HTML directory; simply uncommenting the call will not work after the
  clean stage. Revisit pipeline order and the CSS-to-page/language mapping before enabling
  it. `critical.scss` also has no same-basename `critical.html` page. Do not treat
  `postcss-discard-unused` as a substitute for this HTML-aware step.
- **LRU cache (`lru-cache`, `modules/CustomNewer.js`):** used by a standalone custom
  “newer-file” transform, which is not imported in `gulp/tasks.js`.
- **Conditional stream helper (`modules/CustomIf.js`):** custom transform source exists but
  is not imported by the active tasks. It uses Node streams and has no separate package
  dependency.
- **CSS loaders (`css-loader`, `style-loader`):** rules are configured in Webpack, but no
  current JavaScript entry imports CSS. Styles are built by the Sass/Gulp path.
- **Archive and cleanup utilities (`gulp-zip`, `rimraf`):** neither is called by the active
  tasks; cleanup uses Node's built-in `fs/promises.rm`, and no zip task is currently defined.
- **Terser Webpack plugin (`terser-webpack-plugin`):** no active project import/configuration
  uses this direct dependency. Production minification is enabled through Webpack's
  production mode; the package's presence in `package.json` should not be read as a custom
  Terser configuration.

The packages above are documented for clarity and are intentionally not removed. If an
optional workflow is activated or retired, update this inventory together with the task and
configuration changes.

## 6. Commands

| Command | Effect |
|---|---|
| `npm run dev` | Version check, clean, development build, BrowserSync, watchers |
| `npm run pipesDev` | Version check and development build only |
| `npm run build` | Version check, production build, BrowserSync preview |
| `npm run pipesBuild` | Version check and production build only |
| `npm run clean` | Remove generated `dist/`, `zip/`, and `src/temp/` |

For HTML, style, image, and deployment details, see the corresponding guides in this
documentation series.
